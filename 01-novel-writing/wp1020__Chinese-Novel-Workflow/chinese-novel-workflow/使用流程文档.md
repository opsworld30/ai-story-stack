# chinese-novel-workflow 使用流程文档

当前版本：`0.6.26-chapter-detailed-plot-gate`

## 核心流程

```text
项目规格
-> 项目文件结构
-> 作品定位
-> 设定 / 世界观 / 人物
-> 总纲
-> 独立章节大纲（含本章详细剧情说明）
-> 章节细纲（展开本章详细剧情说明）
-> 单章 AI 创作指令
-> 单章正文
-> 内容连贯性审核
-> 自然化 / 去 AI 润色
-> 硬核终审
-> 章节记忆
-> 全局设定库更新
```

## 正文输出硬规则

正文文件只写故事，不写元信息。

禁止出现在 `正文/` 文件里的内容：

```text
本章字数
字数统计
番茄计字法
本章最低字数
字数规则
章节备注
创作说明
以下是正文
正文如下
本章完成
生成说明
```

字数可以出现在：

```text
设定/04-创作规格.md
章节大纲
章节细纲
AI 创作指令
连贯性审稿
终审记录
```

但不能写进正文。

## 章节大纲与详细剧情说明

章节大纲不只回答“这一章有什么”，还必须回答“这一章从开头到结尾具体发生什么”。每个独立章节必须有`本章详细剧情说明`，按时间顺序写清：

```text
开场压力 -> 事件触发 -> 主角行动 -> 阻碍/反应 -> 冲突升级 -> 关键选择 -> 直接结果 -> 结尾状态
```

它不是正文，也不是场景标题列表。至少要能判断主角做了什么、被什么阻碍、在哪个节点做出选择，以及选择造成了什么结果。若只有一句摘要、关键词或“发生冲突/继续调查”之类空话，先补充剧情说明，再生成章节细纲。

推荐字段：

```markdown
- 本章详细剧情说明:
  1. 开场压力与事件触发:
  2. 主角行动与主要阻碍:
  3. 冲突升级与关键选择:
  4. 直接结果与结尾状态:
```

生成章节细纲时，要把这份说明拆成场景动作链；不得擅自增加重大事件、揭示、关系变化或结尾结果。生成 AI 创作指令时，必须继续引用这份说明，并逐项核对章节细纲是否完整承接。

## 章节去重规则

每一章都必须承接前章压力，但不能重复前章剧情。

```text
上一章负责完成事件；
本章负责产生新变化。
```

生成章节细纲时，先确认本章详细剧情说明已经完整，再核对：

```text
上章已完成什么；
本章新增什么；
本章禁止重演什么；
本章最后产生什么新结果。
```

生成 AI 创作指令时，必须写清：

```text
上一章已完成事件
本章必须新增的事件
本章禁止重演的事件
本章必须把剧情推进到哪里
```

写正文时，开头不要从“上一章发生了什么”的总结进入，而要从下面至少一个入口进入：

```text
新压力
新动作
新信息
新误判
新决策
新后果
```

审稿时如果发现本章只是把上一章高潮换一种说法重演，应标为 High；如果已经破坏章节边界、节奏或钩子功能，应标为 Blocking。

## 正文创作指令示例

```text
使用 chinese-novel-workflow，依据第XXX章 AI 创作指令写正文，只给正文。不要输出本章字数、番茄计字法、章节备注或任何生成说明。
```

## 审稿检查

内容连贯性审核时，除了检查人物、伏笔、衔接和字数是否达标，还要检查正文是否泄漏元信息。

如果发现：

```text
本章字数：3086字（番茄计字法）
```

处理方式：

```text
从正文删除；
如需记录字数，放到审稿报告或终审记录；
不把它写入正文文件。
```

## 被字句误伤保护

去 AI 审查时，不要把所有“被”字句都当成病灶。

应保留的被字句：

```text
表达受害、受压、受控、受辱、被迫、被困、被抓、被推、被打断；
主语的承受状态比施动者更重要；
施动者未知、不重要、不能暴露，或当前 POV 无法确认；
“被”本身带有情绪、压迫、无力感、讽刺感或人物口吻；
固定表达或顺口中文，如“被困”“被迫”“被打断”。
```

只处理这些问题：

```text
无谓被动；
欧化被动；
被动感官中介；
改成主动后动作链更清楚，且不损失语义的句子。
```

判断口径：如果只是因为句子里有“被”字才想改，禁止修改。
## 夸张修辞保护

去 AI 不等于去掉夸张。

正常网文允许：

```text
夸张形容
强情绪
戏剧化表达
重复强调
爽点式用力
角色口吻里的过火表达
```

只有这些情况才需要修改：

```text
空泛；
套话；
没有动作支撑；
没有人物声线；
没有场景后果；
放到任何章节都能用。
```

判断口径：

```text
如果夸张服务于人物、压力、爽点、悬疑、羞辱、喜剧、情绪落点，就保留。
如果只是空喊“极其复杂、无比震撼、前所未有”，才改。
```
## 正文内结构元叙事禁止

正文叙述、人物心理、普通对白不能出现作者/大纲/目录视角。重点拦截这些非标题、非正文内可见文本的表达：

```text
第几卷
第几章
本卷
下一章
后续剧情
阶段收束
主线节点
读者会看到
本章真正的冲突
```

只有它们是故事内可见文本、系统界面、档案名、书名、公告、任务面板、卷宗标题，或作者明确允许的元叙事时，才可保留。

修改方向：不要把这些词润色得更顺，而是改成角色当下能感知的动作、压力、信息、判断或后果。

错误示例：

```text
这是第二卷真正的转折点。
下一章的危机已经埋下。
本章真正的冲突才刚刚开始。
```

可改方向：

```text
从这一刻起，没人还能把事态按回原来的轨道。
门外那道脚步声停住了，停在他看不见的地方。
他刚把话咽回去，屋里第二个人已经站了起来。
```
